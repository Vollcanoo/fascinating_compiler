# 优化实现边界

本项目的性能提升全部来自静态程序分析和编译器代码变换。编译期不解释执行、不 JIT 执行
ToyC 程序：编译器从不运行被编译的程序。

常量求值只在**所有操作数都已被证明为常量**时进行，适用范围限于 `const` 初始化、全局静态
初始化，以及数据流分析确定为常量的表达式。函数调用和有副作用的操作不会通过执行程序来
求值；全局变量的读写在任何可能被观察到的位置都会保留。

循环是这条界线上唯一需要单独说明的一项。迭代次数静态可知、且循环体是**纯算术直线代码**
的循环，会被替换成它所计算的递推式的**闭式解**（标量演化 / 最终值替换，即 GCC 的
`scev_const_prop` 与 LLVM `IndVarSimplify` 里的 `rewriteLoopExitValues`）。区分它与
「解释执行」的判据是代价：闭式求值的开销只与递推式的**次数**有关，与迭代次数无关——
10⁹ 次的循环和 10 次的循环折叠起来一样快，因为编译器推导的是递推关系的形状，而不是
逐次迭代地重放它。

这条变换的直接后果是：如果 `main()` 的循环全部满足上述条件，它确实会被折叠成一条返回
常数的指令。这是变换的推论，不是为哪个测例开的特例。反过来，只要循环体里有调用、有全局
写、或有自己的控制流，它就不满足前提，循环照常保留——`test_codegen.ml` 对这三种情况都有
断言。

## 已实现的优化

### 过程内（`lib/backend/optimize.ml`）

- 局部常量传播、复制传播、常量折叠（按 int32 语义，与目标机溢出行为一致）；
- 代数化简与强度削弱（`x*2^k → x<<k`、`x+x → x<<1`、恒等式与恒真/恒假比较等）；
- 常量除法/取模的倒数乘法替换：RV32 没有快速除法器，`div`/`rem` 要几十个周期，而
  `mulh` 只要几个。除数已知时，商可以用「乘以定点倒数再移位」算出来
  （Hacker's Delight 图 10-1）。该构造对**全部 2³² 个被除数**都精确等于截断除法，
  这才是敢用它替换除法指令的前提，`test_codegen.ml` 里有约 25 万组组合的扫描验证。
  除数为 2 的幂时改用移位加符号修正序列。注意这一项会让**指令条数变多**、
  但周期数大幅下降；
- 展开放在 IR 层而非后端，这样公共子表达式消除能共享同一个值的 `/k` 与 `%k` 之间的
  符号修正，倒数常量本身也变成普通的循环不变量被提出循环；
- 恒非负分析：向零取整正是有符号除法昂贵的根源——`x / 2^k` 要先加偏置、`x % 2^k` 还要
  再减回去、倒数序列结尾要补符号修正。被除数若不可能为负，这些步骤全是空转。分析取两个
  来源：一是结构性的（掩码、比较结果、非负常量），二是循环计数器。对计数器的证明需要论证
  **不溢出**而不只是初值——初值非负、步长为正、且循环条件把它压在一个常量上界之下，
  使得下一次自增不会绕回负数，三者缺一不可。收益：非负被除数下 2 的幂除法从 4 条塌缩到
  1 条、取模从 6 条塌缩到 1 条，一般情况省去结尾的符号修正；
- 计数器取模的强度削弱：`i % k` 中 i 若是定步长计数器，则它本身就以 k 为周期循环，
  可以随计数器增量维护而不必每轮重算倒数。这是把经典的「`i * k` 转累加」强度削弱推广到
  取模。正确性依赖计数器恒非负（否则 C 的余数会变号，跟不住）以及 `0 < 步长 < k`
  （这样一次条件减法就足以把running值拉回区间）。模数为 2 的幂时不做——那种情况本来
  就只要一条掩码，维护 running 值反而更贵；
- 局部公共子表达式消除，以及基于可用表达式数据流的全局公共子表达式消除；
- 带可达性的控制流敏感常量传播：条件为常量的分支只沿实际可达的一侧传播，
  另一侧连同其代码一起删除；
- 死定义删除（基于活跃变量分析）、死全局存储删除、不可达代码与无用标号删除；
- 分支跨越跳转的合并：`若条件成立跳到下一个标号，否则无条件跳走` 合成一条反向分支，
  裸 `break` / `continue` 都是这个形状；
- 全局变量循环内寄存器提升：循环内对全局的每次读写都要先materialize地址再访存。若循环内
  没有任何东西能观察到该内存位置，就在循环前载入寄存器、循环内只动寄存器、出口处写回。
  三个前提缺一不可——循环内不能有调用（被调用者可能读写同一个全局）、不能有 return
  （会带着寄存器里的新值离开而内存还是旧值）、离开循环的边必须**只有**回边所在那一条
  （`break` / `continue` 会绕过写回点）。循环整体被守卫跳过是安全的：那样连循环前的
  载入也一并跳过了，根本没有缓存过；
- 赋值临时量折叠：`t = expr; x = t` 合并为 `x = expr`；
- 循环不变量外提（含在循环内不被写、且循环内无调用时的全局读）；
- 循环旋转：把顶测循环改写为底测循环，消去每次迭代的无条件回跳；
- 循环内立即数物化：把后端无法编码进指令、必须用 `li` 装载的立即数提升为临时量，
  再由循环不变量外提移出循环。被折进条件分支的比较，其边界也算在内——分支比较的是
  两个寄存器，`slti` 那套立即数形式用不上；
- 只做零判断的取模改写：`x % 2^k` 需要六条指令做符号修正，但 `x % 2^k == 0` 与符号
  无关，一条掩码即可。仅当该余数的**每一处**使用都是零判断时才改写；
- 循环闭式求值（`lib/backend/scev.ml`）：循环体若是纯算术直线代码，它每一轮对某个值的
  增量若本身是迭代下标的多项式，那这个值就是高一次的多项式。用**二项式基**
  `f(n) = Σ aₖ·C(n,k)` 表示这个多项式，是整件事便宜且精确的关键——该基下的系数正是 f 在
  0 处的各阶差分，于是「每轮累加 P」就等于「把初值接在 P 的系数前面」，不需要除法、不需要
  有理数、也不用去凑 Faulhaber 求和公式。系数全部模 2³² 保存：循环里溢出的累加器，闭式里
  必须照样溢出，否则改写会改变结果。乘法是二项式基下唯一不平凡的运算，走「取样—逐点相乘—
  差分回系数」，每一步都还是模 2³² 的环运算，因此仍然精确。
  三个前提：循环体必须纯（无调用、无全局访问、无自身控制流），删掉它才不会丢掉可观察行为；
  每个活到循环之后的值都必须有闭式，否则改写会留下未定义的量；推出的递推式在重写前要再跑
  一遍符号求值验证——第 n 轮末的值必须等于第 n+1 轮头的值；
- 计数循环展开：紧凑循环每一轮都要为底部的判断和回跳买单，一次判断跑多份循环体就把这笔
  开销摊掉了。因为各份副本复用同一批虚拟寄存器，展开**不增加寄存器压力**——活跃区间变长，
  但没有新的值出现。展开倍数必须整除迭代次数（否则丢掉中间的判断会跑过头），除不尽的
  余数在循环前**剥离**成独立的几份。计数器若除了自增和判断之外无人观察，各份副本连自增
  一起省掉，由最后一份一次走满整个倍数；体内的提前退出（`break`、`return`）不受影响，
  它们本来就在哪一份里就从哪一份离开;
- 上面两项都依赖同一个前提，也是唯一可能悄悄产生错误代码的一个：**计数器每次进入循环时
  必须取同一个初值**。仅靠「初值定义支配循环头」是不够的——内层循环的计数器若声明在外层
  循环之外，第二次进入时它已经停在上界了。因此还要在 CFG 上确认：绕开全部初始化定义、
  且不走回边，无法再回到循环头。`t39_loop_entry_value.tc` 里两个只差一行声明位置的嵌套
  循环，答案分别是 520 和 504；
- 参数活跃区间拆分：参数若在提前返回路径上被读、又在调用之后被读，其活跃区间跨越调用，
  分配器只能给它被调用者保存寄存器，连带把入口拷贝和保存/恢复的代价压到提前返回路径上。
  在含调用的区域入口处拷贝一次即可拆开区间，入口那一半不跨调用，可以留在传入的实参
  寄存器里。仅对参数、仅在不位于任何循环的拆分点、且剩余区间确实不跨调用时进行，
  因此不会产生负优化。

### 过程间

- 小函数内联（不含调用的非 `main` 函数，直线代码代价 ≤ 40 条指令，含循环者 ≤ 20 条）。
  内联含循环的小函数不只省下调用序列，更重要的是常量实参能传播进循环体；
- 尾递归改写为循环；
- 从 `main` 不可达的函数删除。

### 后端（`lib/backend/regalloc.ml`、`lib/backend/codegen.ml`）

- 基于指令级控制流图的活跃变量分析与图着色寄存器分配；
- 按循环深度加权的溢出代价，内层循环中的值优先保留在寄存器中；
- 寄存器合并偏好：入口参数、返回值、调用实参与调用结果尽量直接落在 ABI 规定的
  寄存器上，从而消去调用点周围的 `mv`；
- 调用者保存寄存器（`a0`–`a7`、`t3`–`t5`）只分配给不跨调用存活的值；`a` 寄存器还要求
  该值在每个调用点都出现在同一实参位置，避免实参装载互相覆盖；
- 栈帧按需建立：不溢出、不使用被调用者保存寄存器的叶子函数完全不建栈帧；
  只有存在溢出槽时才建立帧指针 `s0`；
- 栈帧延迟建立（shrink wrapping）：序言下沉到支配所有"需要栈帧"指令（调用、溢出槽
  访问、写被调用者保存寄存器）的最深那条指令之前，建帧点到不了的返回直接 `ret`。
  三个前提：建帧点每次调用至多执行一次（因而不能位于循环内）、它能到达的每个返回都
  必须被它支配（否则同一个返回时而需要尾声时而不需要）、函数没有栈上传递的参数
  （那些参数的读取偏移取决于栈帧是否已建立）；
- 拷贝合并：`dst = src` 这条 move 不在其两端之间引入干涉边——move 之后两者值相同，
  共用寄存器正好让这条 move 变成空操作。若两者此后不再相等，重定值会在那一点补上边；
- 指令选择：立即数直接进指令（`addi`/`slti`/`slli`）、2 的幂乘除模转移位、
  比较与条件分支融合（`slt` + `beqz` + `j` 三条合为一条 `blt`/`bge`）、
  尾调用后直接返回；
- 汇编级窥孔：消除互逆的 `mv`、`sw`/`lw` 同槽往返。

## 测试要求

回归测试必须覆盖带函数调用和全局副作用的程序，并确认 `-opt` 的输出仍然保留必要的运行时
存储与读取，不会退化成 `main` 直接返回预计算的常数。每个回归程序都在 `-O0` 和 `-opt`
两种模式下执行，结果与独立的 AST 参考解释器比对。

`test/regress/` 下的 RV32IM 模拟器与参考解释器只在编译完成后的回归与基准测试中使用，
不会被生产编译器链接或调用。生产入口固定为：

```text
源码 -> 语义检查 -> IR -> 静态优化 -> 寄存器分配 -> RISC-V 汇编
```
